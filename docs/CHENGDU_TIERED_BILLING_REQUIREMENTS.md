# 成都居民阶梯计费：条件清单与系统落地要求

日期：2026-09-20。

状态：供开发前确认的需求草案；不是已实现功能或生产计费配置。依据为 [政策研究记录](CHENGDU_TARIFF_RULES_RESEARCH.md)，本次未修改业务代码、数据库或185服务。

## 1. 范围与证据等级

首个落地范围：成都市中心城区居民一户一表，默认4人、年度累计阶梯、多人口年度定额核准、历史计费依据留存。区域外、合表和特殊优惠等列入适用性判断，未建立经核实规则的对象不能自动套用此模板。

本文列出当前已识别的政策、计量、计费与账务条件，并不声称覆盖全国供水政策。

- **政策已核实**：来自下面的官方原件或办事规定。
- **系统要求**：为可重复计算、历史追溯和操作一致性提出的产品要求，不冒充政策条款。
- **待核实/待决**：资料没有给出足够细节，或需要选定产品处理方式；未解决前不得静默选择可能改变金额的算法。

官方依据：

- S1：[当前收费标准](https://www.cdwater.com.cn/htm/oneitem_020302.html)。
- S2：[成发改价格〔2015〕1067号](https://www.cdwater.com.cn/htm/detail_2542.html)，适用对象、年度累计和人口基数。
- S3：[成发改要素价〔2020〕516号](https://www.cdwater.com.cn/htm/detail_8340.html)，延长执行至2030-12-31及中心城区“5+1”价格组成。
- S4：[多人口用水量定额办理程序](https://www.cdwater.com.cn/htm/detail_51382.html)，核准、生效和续办。

## 2. 因素总表

“待核实”场景的拦截仅作用于待引入的成都政策模式，不表示现在修改现有Pilot业务。

### A. 决定适用哪套规则

| ID | 条件 | 应保存或识别的事实 | 落地要求与证据 |
| --- | --- | --- | --- |
| A01 | 租户、供水企业 | 租户ID、供水主体 | 不跨租户选资费、累计用量或读取人口资料；系统要求。供水主体与行政区不能相互替代。 |
| A02 | 供水区域 | 结构化政策区域、适用版本 | 不通过地址关键字猜水价；不同区域可有不同收费，S1/S3。 |
| A03 | 用水性质 | 居民、非居民、特种等及生效历史 | 区分生活用水和经营用途，S1；用途变化后不得用当前类别改算所有历史账单。 |
| A04 | 执行居民价的特殊对象 | 适用对象分类、资格依据 | 执行居民价不等于执行居民阶梯，S1/S3；不能只存一个“居民”标签。 |
| A05 | 一户一表/合表 | 结算计量模式 | 两者不能共用阶梯适用判断；本轮官方表中合表为单一居民价格，S1/S3。 |
| A06 | 混合用途或尚未认定用途 | 认定状态、用途证明 | 首批不自动拆分家庭/商业用量；认定与分摊办法需另行核实。 |
| A07 | 特殊减免、补贴、优惠 | 优惠依据、资格、期限 | 单独识别，不假设人人有优惠，不擅自扩大阶梯额度；本轮未核实可执行标准。 |
| A08 | 政策有效期及文件版本 | 文件号、有效区间、来源 | 制度有效期与具体价格版本分别管理；超过已配置有效期应提示配置问题，S3/系统要求。 |

### B. 决定谁享有多少年度额度

| ID | 条件 | 应保存或识别的事实 | 落地要求与证据 |
| --- | --- | --- | --- |
| B01 | “一户”的归属 | 住宅/用水户身份及关联水表 | 原则按住宅认定，S2；不能默认一个客户或结算户共用一份额度。首批限定一个明确用水户对应一个政策户。 |
| B02 | 实际人数与核准人数 | 申报人数、获批人数 | 两者分开；超过4人需核准才扩档，S4。人数不超过4时不缩减标准额度。 |
| B03 | 人口定额申请状态 | 申请、受理、核准/驳回记录 | 草稿、待核准、被驳回均不能触发加量；系统状态设计建议。 |
| B04 | 证明材料及地址一致性 | 证明类型、校验结果、必要引用 | 按S4记录核验结果与材料有效期；不在普通账单或日志暴露证件内容。 |
| B05 | 核准年度 | 所属结算年度 | 不把2026获批人数自动带入2027，S4。 |
| B06 | 核准及生效节点 | 批准时间、触发生效的抄表事实 | 批准后的下一次抄见表生效，S4；不能简单等同于提交表单时间或整月开始。 |
| B07 | 到期与续办 | 年度截止、续办关联 | S4规定本年度有效、期满前30日内续办，逾期恢复标准；年度核准记录须保留。 |
| B08 | 人口增加、减少、撤销、更正 | 新旧值、业务时间、原因、操作者 | 新增记录/更正链，不覆盖旧依据；减少、撤销、追溯的具体政策待核实。 |
| B09 | 多表、多住宅、客户/结算户变化 | 额度归属关系及历史 | 换收款人或结算户不能随意创造新额度；共享、拆分、合并及过户规则待核实。 |
| B10 | 默认基数和扩档参数 | 默认4人、216/300、每人51 | 参数属于政策版本；经核准后两个累计上限分别平移，S1/S2/S4。 |

### C. 决定计费水量和累计位置

| ID | 条件 | 应保存或识别的事实 | 落地要求与证据 |
| --- | --- | --- | --- |
| C01 | 本期水量来源 | 实抄、估水、调整及来源单据 | 区分可信读数与估计值；界面不得把估计止度伪装成实际抄见。 |
| C02 | 上下次读数及日期 | 原始读数、抄见日期、计量跨度 | 表码是累计数，阶梯以用量计；记录日期与账期不能混为同一字段。 |
| C03 | 抄表周期和结算账期 | 月/双月/跨月跨度、归属期 | 年阶梯不能每张账单重置；跨度内发生调价/跨年时需明确分配依据。 |
| C04 | 年度累计 | 同一政策户的有效历史计费水量 | 年度内累计，跨年不结转，S2；系统目前按自然年账期计算。跨年抄表水量如何归属仍需明确。 |
| C05 | 补录、乱序开账、导入历史 | 源期、历史完整性、期初年累计 | 不因缺少前期账单就默认年累计为0；历史缺口和乱序应提示，必要时阻止成都模式开账。 |
| C06 | 未抄见与估水算法 | 未抄见原因、算法版本、样本、估计量 | 最近三期平均是现有系统方法，不是本次核实的成都政策；无样本、异常样本和舍入需明确。 |
| C07 | 恢复实抄与补差 | 实读锚点、覆盖源期、已估水量 | 先确定各期真实水量，再逐期计算差额；跨年不能把所有负差当成当年负用水。 |
| C08 | 换表、回卷、倍率、异常读数 | 旧表止度、新表起度、换表点、设备参数 | 正确计算消费量；换表不等于新政策户，不重置年度累计。倍率、回卷支持情况须在开发前逐项确认。 |
| C09 | 新开、停用、恢复、销户 | 事件日期及当时计量状态 | 不自行按月/按日减少年度额度；折算和停复水规则待核实。 |
| C10 | 漏水、故障、错抄、更正 | 更正依据与审批、原始事实 | 不把所有异常都直接免除或减量；可改水量还是只减金额须有独立依据。 |
| C11 | 物理用水量唯一性 | 结算/修正事实而非费用行数量 | 同一吨水可产生水费、污水费等多行，但年度累计只增加一次；替换账单也须遵守。 |

### D. 决定每档价格与最终金额

| ID | 条件 | 应保存或识别的事实 | 落地要求与证据 |
| --- | --- | --- | --- |
| D01 | 价格版本和适用日期 | 资费版本、有效起止、价格依据 | 已有版本机制需复用；跨调价日的一期不能仅按最新版本整体计费。分段细则未核实时须显式处理。 |
| D02 | 连续阶梯边界 | 0、第一上限、第二上限、无穷上限 | 分档连续无空隙，无重叠；216.5中的0.5属于第二档，不把“217起”当程序下限。 |
| D03 | 累进分档方式 | 本期各档水量、单价 | 只对各档占用量按该档计价，不把整期水量乘最高档单价。 |
| D04 | 多人口年度额度变化 | 本期有效上限及本年前期已计量 | 获批前不追溯退差，S4；获批后保留原年累计，再按新上限分配后续用量，不重置累计。 |
| D05 | 费用组成 | 阶梯水费、污水费或更细明细 | S3中倍率仅作用于运营水费；不能对终端价整体乘1.5/3，也不能重复收取已包含费用。 |
| D06 | 费用计量基数 | 各费用项的计费水量/算法 | 不假设未来所有费用都使用同一水量；首批只纳入有明确依据的费用项。 |
| D07 | 单位、精度和舍入 | m³、元/m³、金额分、舍入规则版本 | 用精确十进制；沿用现有逐费用/阶梯行舍入时应明确这是系统方案，官方细粒度尚未核实。 |
| D08 | 特殊费用和减免 | 固定费、附加费、违约金、优惠等 | 与阶梯用量计算分开；已有计算能力不代表当地有权收取该费。 |

### E. 决定历史重算和收款展示是否正确

| ID | 条件 | 应保存或识别的事实 | 落地要求 |
| --- | --- | --- | --- |
| E01 | 已入账、部分缴费、已缴清 | 账单状态、分摊记录 | 未缴清不减少年度用量；收款状态不决定阶梯档位。 |
| E02 | 收款红冲与账单撤销 | 冲正对象及关联原单 | 仅撤销一笔收款不撤销消费量；账单替换/撤销涉及计费事实，须区分。 |
| E03 | 历史水量/人口/用途更正 | 源期事实与当期调整单 | 不使用当前人数、用途、单价直接改算所有历史；纠错须能说明改变了什么依据。 |
| E04 | 同年后续账单影响 | 修正源期之后的有效账单 | 调整前期水量可能改变后续阶梯占用；计算影响范围，不能只改单期后悄悄留下后续金额不一致。自动重算范围需专项设计。 |
| E05 | 负补差、退款、余额抵扣 | 调减应收、实际已付、可退/可抵金额 | 负补差不等于已经退款，账单减少不等于现金流出；展示与操作分别定义。 |
| E06 | 重复操作和并发 | 幂等标识、被读取的规则版本 | 核准、续办、开账、补差重复点击不重复增额或重复产生单据；并发更改不能产生混合版本账单。 |
| E07 | 历史证据和权限 | 依据快照、操作者、时间、原因 | 读表、收费、资费发布和核准权限分开；未授权直链及API均不得修改定额。 |
| E08 | 报表归属 | 业务源期、调整发生期、实际收款期 | 原年度用量、当期调整应收和当期实收不能混为同一统计口径，报表应说明。 |

## 3. 成都首个政策模板

只对已确认适用对象使用此模板；金额为官网当前公示参数，不从旧2015价格表复制历史终端价。

| 参数 | 数值 |
| --- | --- |
| 默认人口基数 | 4人 |
| 年度第一、二累计上限 | 216、300m³ |
| 每超1名核准人口的年增量 | 两个累计上限各加51m³ |
| 阶梯自来水费 | 2.08、2.95、5.56元/m³ |
| 污水处理费 | 0.95元/m³ |
| 对应终端价 | 3.03、3.90、6.51元/m³ |
| 人口核准期限 | 本结算年度；下一次抄见表开始适用 |

E = max(核准人数 - 4, 0) × 51；T1 = 216 + E；T2 = 300 + E。没有有效核准时E=0。

令Y为本期开始前已确认的同年累计用量，Q为本期计费量（均非负）：

```text
第一档量 q1 = min(Q, max(T1 - Y, 0))
第二档量 q2 = min(Q - q1, max(T2 - max(Y, T1), 0))
第三档量 q3 = Q - q1 - q2
水费 = q1 × 2.08 + q2 × 2.95 + q3 × 5.56
污水费 = Q × 0.95
```

实际落账须应用已选定的舍入规则；上式用于解释分档，不允许浮点数直接结算。负修正走历史重算与差额单，不直接给本公式传负Q。若一期内核准生效或调价且需要拆段，应先拆出有依据的水量段，再按时间顺序计算。

## 5. 计算与操作顺序

1. 确定租户、供水区域、用水性质与政策户，检查是否在支持范围。
2. 确定消费跨度、源账期及计费年度；发现资料缺口或需待定算法时标出原因。
3. 选择适用的资费版本与人口核准记录；候选冲突、跨版本或生效节点不明时不靠“取最新”消除歧义。
4. 取得可追溯的年累计前值，解析当期T1/T2；不把缴费进度或费用行数作为用量。
5. 根据实抄、估水或已核准修正确定Q；执行连续分档及费用计算。
6. 展示预览及依据。保存账单时原子保存计算依据，并防止同期并发产生重复/冲突结果。
7. 补差先计算源期及后续账单影响，再生成调整单；涉及退款或抵扣时进入独立操作。

前端应能回答：“为什么我这期用了第二档？”至少展示本年前值、本期量、核准人数及期限、两个年上限、各档量与金额、实抄/估水标识和资费依据。缺资料时给中文原因和处理入口，不给一个静默的0元结果。

## 6. 必须明确的政策/产品决策

| ID | 尚未确定的事项 | 需要的证据/决策 | 未明确时的产品边界 |
| --- | --- | --- | --- |
| U01 | 年中新开户、停复水、销户额度折算 | 供水企业执行办法 | 不自行除以12或365；涉及折算争议的正式计算不自动放行 |
| U02 | 获批后下一次未抄见/估水是否触发生效 | 对“抄见表”的业务解释 | 不把所有计划完成状态都视作实抄；生效节点待核实 |
| U03 | 跨年、跨调价日、跨核准节点的水量拆分 | 时间归属/分摊办法 | 禁止默认均分或全放一个月；可先提供待核定状态 |
| U04 | 估水样本、算法、上限和舍入 | 正式估水执行办法 | 既有AVG3仅作为已标注的系统规则/测试假设，不宣称政策认证 |
| U05 | 人口减少、资格撤销、错批和追溯 | 资格变更执行办法 | 保留历史，禁止覆盖人数后自动重算历史账单 |
| U06 | 多表同宅、合户分户、过户额度承接 | “一户”认定及额度承接办法 | 首批仅支持明确的一户一表对应关系，不自动复制/共享额度 |
| U07 | 舍入粒度与费用拆项 | 收费账单样例或执行标准 | 拆项方案和舍入方式需作为明确版本；先用边界案例比较分差 |
| U08 | 前期更正对同年后续账单的连锁处理 | 确定影响范围、审核和调整流程 | 先给影响清单，不只修单期后声称整个年度正确 |
| U09 | 负补差退款、挂账或抵扣 | 财务处理选择和权限 | 不把生成负账单当成退款完成 |
| U10 | 年中迁入系统的历史累计 | 导入凭据、核准资料、切换时点 | 无历史证据不得把累计填0；有证据才可录入经审核期初值 |
| U11 | 优惠、漏损减免、混合用途及特殊费 | 对应政策原件与适用资格 | 不以自由填写减免百分比代替制度 |

这些决策可分批确认；无关边界不应阻止标准整年场景开发，但不能将未支持边界包装为自动正确计费。

## 7. 方案选择与推荐范围

| 方案 | 能力与代价 | 结论 |
| --- | --- | --- |
| 年度核准记录 + 规则解析 + 账单依据 | 能表达生效、到期及历史复算；需新增有针对性的数据与业务流程 | 推荐 |
| 仅在用水户加人数 | 开发快，但不能正确表达审批和历史有效期 | 只适合演示，不适合本轮正式目标 |
| 每个人数复制一套资费 | 可临时算出不同档位，但维护、续办和历史关联困难 | 不推荐作为长期方案 |

建议分阶段交付，每阶段单独验收：

1. **标准居民人口阶梯**：政策适用与版本、年度核准及生效/到期、档位解析、账单说明与快照；先验证整年、明确抄见生效的正常场景。同期包含基本跨租户/权限、准确年累计和并发保护。
2. **历史与复杂事件**：在U01—U08中有关规则明确后，覆盖跨年估水、年内调价、核准中途变化、历史补录及后续账单连锁调整。不改变此前已核实的价格事实。
3. **财务与特殊对象**：按正式办法接入退款/抵扣、混合用途、合表、优惠及其它地区模板。已有非成都资费继续按原明确配置运行。

第一阶段中途获批的真实用量场景可以纳入，但只有在生效抄表与水量段可明确对应时自动计算；估水或跨节点归属不清时使用待核定状态。

## 9. 迁移与发布约束

- 以现有185的Pilot数据为需要保留的业务历史；研究和开发不直接更新该库资费。
- 新数据结构采用兼容迁移；旧账单缺少新增快照时明确标记旧版依据，不能伪造当时已核准的人口。
- 历史客户不自动认定为5人，既有资费不自动改成成都模板；适用关系和切换账期需要明确。
- 已入账、已缴费、已日结历史不原地改金额；必要修正走有来源的业务单据。
- 不重置Pilot、不重新seed、不覆盖管理员密码；发布前备份并准备回退路径。
- 在隔离测试库验证迁移及回归，通过后再安排185发布。旧版本tag保持不动。
