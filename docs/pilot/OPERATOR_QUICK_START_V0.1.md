# 水务业务系统 Pilot 操作员快速开始 V0.1

> 本说明仅用于第一轮内部试运行。
> 目标是帮助操作员开始使用系统，不是完整操作手册。
> 如果遇到“不知道下一步做什么”“看不懂字段”“找不到入口”等情况，请先记录，不要立即让开发人员代替操作。

## 1. Pilot 环境

内网访问地址：

```text
http://192.168.3.185:5185/login
```

当前为 **内部试运行环境（Pilot）**，不是正式生产系统。

登录需要：

```text
租户代码
账号
密码
```

具体测试账号由管理员单独发放。

请勿多人共用同一个操作员账号。

# 2. 系统主要业务流程

日常业务大致按照以下顺序：

```text
客户 / 水表户建立
        ↓
水表登记与安装
        ↓
加入抄表册
        ↓
生成抄表计划
        ↓
抄表录入
        ↓
抄表质检
        ↓
生成结算
        ↓
终审
        ↓
生成开账批次
        ↓
执行开账
        ↓
收费 / 预存
        ↓
查询 360° / 报表 / 异常
```

不同岗位通常只负责其中一部分。

---

# 3. 常用功能

## 客户与水表户

用于：

```text
新客户立户
建立水表户
安装水表
查看客户当前状态
```

常用入口：

```text
客户管理
→ 立户向导

客户管理
→ 水表户
```

完成立户后，应至少能看到：

```text
客户
户号
用水地址
水表
在装状态
```

水表户列表中的 **360°** 用于查看该户的综合信息。

---

## 抄表

典型流程：

```text
抄表册
→ 加入水表户
→ 生成计划
→ 开始计划
→ 录入读数
→ 质检
```

正常读到表码时选择正常读数。

无法正常抄表时，应根据实际情况选择未抄见原因。

不要为了让流程继续而随意填写不存在的表码。

---

## 抄表质检

质检人员可根据实际情况：

```text
通过
驳回
复核
```

如果读数被驳回，应通过 **更正读数** 处理。

不要直接修改历史读数。

系统会保留原读数与更正记录。

---

## 结算

正常顺序：

```text
生成结算
→ 检查用量
→ 终审
```

终审后的结算才进入后续开账流程。

如果是估算用量，请特别检查：

```text
预估用量
预估原因
```

---

## 开账

进入：

```text
开账批次
```

正常流程：

```text
新建开账批次
→ 选择账期
→ 生成
→ 检查户数 / 失败户数
→ 执行开账
```

正常情况下应看到：

```text
失败户数 = 0
最终状态 = 已开账
```

如果存在失败户，不要反复点击生成或执行，应先记录问题。

---

## 收费

进入：

```text
收费台
```

正常流程：

```text
选择客户
→ 选择水表户
→ 查看欠费
→ 核对金额
→ 收款
```

系统支持：

```text
全额缴费
部分缴费
多笔账单缴费
预存充值
```

收款前请确认：

```text
客户
户号
欠费金额
本次收款金额
```

如果点击收款后页面卡住、网络中断或结果不明确：

**不要再次立即点击收款。**

先查询：

```text
收款记录
账单
360°
```

确认是否已经成功入账。

---

## 红冲

如果已发生错误收费，可以从收款记录进行红冲。

红冲不是删除历史记录。

正常结果应表现为：

```text
原收款记录保留
产生负金额红冲记录
原收据作废
欠费恢复
```

---

## 日结

收费员完成当天业务后进入：

```text
收费日结
```

执行日结前，应确认当天收费记录无明显异常。

日结后，相关收款将进入已日结状态。

---

## 水表更换 / 拆除

水表档案中可以进行：

```text
装表
拆表
换表
```

换表时注意区分：

```text
旧表止码
新表始码
```

历史抄表和结算记录不会因为换表而删除。

---

## 销户

存在在装水表时，系统不允许直接销户。

正确顺序：

```text
拆表
→ 确认不存在在装水表
→ 销户
```

# 4. 异常中心

异常中心用于提示需要人工关注的问题，例如：

```text
未入抄表册
无在装水表
抄表质检驳回
远传事件异常
账单逾期
```

处理异常时先判断：

```text
发生了什么？
是哪个客户 / 户号？
为什么出现？
应该去哪一个业务页面修复？
```

异常中心支持：

```text
确认
指派
忽略
标记已解决
```

注意：

**标记已解决不是用来强行关闭仍然存在的问题。**

如果异常事实仍然存在，系统可能拒绝标记解决。

---

# 5. 360° 页面

360° 用于查看一个水表户的完整业务信息，包括：

```text
基本信息
水表
抄表
结算
账单
缴费
预存
事件
```

当你不知道某户“现在到底是什么状态”时，优先查看 360°。

---

# 6. 测试期间遇到问题怎么办

第一轮 Pilot 最重要的不是“把流程做成功”，而是发现真实问题。

如果遇到：

```text
不知道下一步点什么
找不到入口
字段不知道什么意思
按钮名称容易误解
操作成功但不知道是否成功
金额不敢确认
系统提示看不懂
需要反复来回切页面
```

请停止猜测，并记录：

```text
当时在做什么
所在页面
你原本想完成什么
你为什么卡住
最后怎么解决
```

不要为了完成测试而让开发人员直接告诉你每一步该点哪里。

这些卡点本身就是 Pilot 最重要的结果。
