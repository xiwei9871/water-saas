# 人工 Operator Pilot 测试任务单 V0.1

> 配套文档：`OPERATOR_QUICK_START_V0.1.md`
> 本任务单给组织者使用；第一轮测试时 **不要** 把 Quick Start 发给操作员。

## 0. 我们要验证什么

自动化测试已经证明"按钮能点、金额正确、状态机对"。
人工 Pilot 要回答的是另一个问题：

```text
一个没参与开发的人，能不能自己理解并完成工作。
```

所以测试目标是观察，不是考核操作员：

```text
在哪一步需要问别人？
哪个词看不懂？
找不到哪个按钮？
为什么犹豫？
误点了什么？
完成一户大概多久？
```

## 1. 测试前准备（管理员）

环境：

```text
地址：http://192.168.3.185:5185/login
```

账号准备——为每个角色建独立账号，禁止共用 admin：

| 操作员 | 岗位角色 | 用途 |
|---|---|---|
| A | 抄表 / 复核 | 抄表、质检、异常修复 |
| B | 收费 / 营业厅 | 收费台、预存、红冲、日结 |
| C | 管理 / 综合 | 立户、开账、异常分派、报表 |

要求：

```text
A / B / C 三人都未参与本系统开发
每人使用自己的账号登录
测试租户由管理员指定（cd-water 或 xh-water）
```

管理员需提前建好：

```text
一个空白测试客户区 / 若干未立户水表
至少一户已有欠费账单的客户（供 B 测试）
至少一个已存在异常（供 C 测试，如未入册户）
```

## 2. 第一轮：无说明测试（最重要）

**不发 Quick Start，不给入口提示。** 只给一句话任务，观察能否自己找到路径。

### 任务卡 0A（发给 A）

```text
你是抄表员。请完成本账期你们营业所的抄表录入，
并把读数交给质检。
```

### 任务卡 0B（发给 B）

```text
你是收费员。有一户客户来缴费，
请找到他，查清欠费，收 1 元。
```

### 任务卡 0C（发给 C）

```text
有一位新用户要开户装表。
请完成立户，让他能被正常抄表收费。
```

### 观察要点

```text
登录后第一眼去了哪个菜单？
用了多久找到第一个正确入口？
有没有走回头路？
是否问了"XX 在哪里"？
```

**组织者纪律**：操作员卡住时，先记录卡点，不直接告诉答案；
确实无法进行时再给最小提示，并记下"提示了什么"。

## 3. 第二轮：带说明书的完整流程

第一轮结束后，把 Quick Start V0.1 发给操作员，执行正式任务卡。

### 任务卡 A — 抄表 / 复核（全流程一户）

```text
1. 在抄表册中确认本所水表户清单
2. 生成本期抄表计划并开始
3. 录入 3 户读数（其中 1 户用"未抄见"原因）
4. 质检：通过 2 条，驳回 1 条
5. 对被驳回的读数做"更正"
6. 复核更正后的读数至通过
```

记录：质检驳回后能否自己找到"更正"入口？未抄见原因选项是否够用？

### 任务卡 B — 收费 / 营业厅

```text
1. 查询指定客户欠费，说出应收金额
2. 全额收款一笔
3. 对另一户做部分收款（任意金额）
4. 预存充值一笔
5. 对刚才的一笔收款做红冲
6. 执行收费日结
```

重点访谈（每步后问一句）：

```text
你敢不敢按"收款"？按之前知不知道要收多少？
收完以后怎么确认成功了？
红冲和退款你分得清吗？
日结后哪些钱被结掉了，你说得出来吗？
```

### 任务卡 C — 管理 / 综合

```text
1. 完成一户新用户：立户 → 装表 → 入册
2. 对该户走通：计划 → 抄表 → QC → 结算 → 终审
3. 新建本期开账批次，核对户数与失败数，执行开账
4. 打开该户 360°，从头复述这户发生了什么
5. 在报表里找到本期应收 / 实收，和 360° 对一下数字
```

异常处理任务（单独给 C）：

```text
"异常中心里有一个未入册异常，请处理它。"
——不给菜单路径、不说该入哪个册。
```

观察他能否自行判断：发生了什么 → 对象是谁 → 属于哪个营业所 →
去哪修 → 修完怎么确认异常消失。
再依次覆盖：确认（ACK）、指派、忽略、标记已解决、修复后复发。

### 全员共用：非正常操作

在各自任务中穿插观察：

```text
连续点两次同一个提交按钮
提交中途刷新页面 / 浏览器后退
输错金额或表码再取消
```

只记录系统表现和操作员反应，不主动纠正。

## 4. 观察记录表（每卡一张）

```text
日期 / 操作员 / 角色 / 任务卡号
任务是否独立完成：是 / 提示后完成 / 未完成
完成用时：
卡点记录（逐条）：
  - 卡在哪个页面 / 哪一步
  - 操作员的原话或疑问
  - 组织者给了什么提示（如有）
误操作记录：
操作员主动提出的问题 / 建议：
```

## 5. 问题严重度分级

| 级别 | 定义 | 例子 |
|---|---|---|
| P0 | 阻断业务或造成账务风险 | 收款重复入账、金额显示错误、无法完成的必经步骤 |
| P1 | 陌生操作员无法独立完成 | 找不到入口、概念看不懂、误操作无挽回提示 |
| P2 | 可用但体验差 | 要来回切页面、术语生硬、提示不明确 |

P0/P1 进修复清单；P2 先记录，测试结束后统一排序。

## 6. 结束标准

```text
三人三组任务全部执行并有记录
所有 P0/P1 卡点已整理成清单
组织者已把"真人问过的问题"汇总
→ 之后才能写正式 V1.0 操作说明书
```

注意：说明书不是终点。第一轮暴露的问题清单才是本轮 Pilot 的主要产出。
