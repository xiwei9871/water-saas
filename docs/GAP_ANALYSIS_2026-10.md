# 营销系统差距分析（2026-10）

对照基准：
- **CJ/T 298-2008《城镇供水营业收费管理信息系统》**（住建部现行行业标准）
- 辽宁省《城镇智慧供水信息化工程建设》分级清单（I/II/III 级）
- 国内营收系统厂商典型模块（营业收费/表务/报装/银水互联/集抄/营销工单/移动缴费）

---

## 一、已覆盖且超标的领域

| 领域 | 我方实现 | 标准/行业水平 |
|---|---|---|
| 客户档案 | 客户/结算户/用水户三层 + 一户多表统一缴费 + 过户/报停/销户事件 | CJ/T 298 要求的全部档案术语均有 |
| 阶梯水价 | TariffPlan + TariffTier + 一户多人口申报（baseHousehold/perPersonQty） | 超过多数县级营收系统 |
| 抄表 | 册+路线 seqNo、计划、手工/导入/APP/远传四通道、估抄规则、QC 复核 | 达到 II 级；缺拍照识别/GPS 轨迹（III 级） |
| 计费 | 开账批次、账单状态机、调账/红冲/换单、代收费(AGENCY) | 达标且状态机更严谨 |
| 收费 | 柜台+现金/POS/转账/线上/代扣五渠道、分摊、收据红冲、预存 FIFO、柜员日结 | 达标 |
| 欠费 | 账龄桶、催缴任务、坏账核销（审批任务） | 达标；坏账之外 CJ/T 298 另有「呆账」概念见下文 |
| 异常治理 | WorkItem 异常队列 + Task 任务中心（自动建单/候选匹配/竞争领取/结算阻断） | **超出标准与多数厂商** |
| 数据查询 | 五主题统一查询+多期横展+模板+权限字段剔除 | **超出**（行业标准只要求统计查询） |
| 报表指标 | 37 项含催缴成功率等 | 达标 |
| 权限/审计 | 三态数据范围 + 全量 audit_log | 达标 |
| 远传 | RemoteSource/Device/Binding/RawEvent 全链 + 冲突检测 | 达到 II 级（CJ/T 298 附录B的现代形态） |

## 二、真实缺口（建议补齐 — 属营收主链断点）

| # | 缺口 | 依据 | 现状 | 建议量级 |
|---|---|---|---|---|
| G1 | **违约金/滞纳金自动计提** | 行业标配；CJ/T 298 欠费管理 | `BillItemType.PENALTY` 枚举已预留但无任何生成路径 | 中：欠费×日费率×逾期天数 → PENALTY 账单项，费率走 tenant_param |
| G2 | **银行代扣出盘/回盘 + 呆账** | CJ/T 298 附录A 规范性接口协议 | BANK_DEDUCT 仅作收款渠道枚举，无文件流 | 中大：扣款文件生成→回盘导入销账→「已扣未回执」呆账态（CJ/T 298 §3 术语明确定义呆账≠坏账） |
| G3 | **渠道/银行对账导入** | 银水互联核心功能；厂商标配 | 无对账文件导入与差异比对 | 中：对账文件上传→逐笔核账→差异入异常队列 |
| G4 | **催缴通知单（打印/留痕）** | 欠费催缴标配 | 催缴任务只有任务态，无通知单产出 | 小-中：催缴通知单 PDF 生成/打印记录挂任务上下文；SmsPort 已预留 |
| G5 | **票据管理（收据号段/发票登记）** | 营收系统普遍要求票证可溯 | Receipt 只有单据实体，无号段领用/作废管理；无发票登记 | 小：收据号段台账 + 发票登记字段（发票号/金额/开具状态），不接税控 |
| G6 | **抄表机文件导出（下装册/上装数）** | CJ/T 298 附录C | 有 IMPORT 上装；无册本下装文件 | 小：按计划导出 csv/txt 供手持机（若不需要手持机可标记不适用） |

## 三、战略级缺口（超出"营收"边界 — 需决策是否纳入范围）

| # | 缺口 | 依据 | 说明 |
|---|---|---|---|
| S1 | **业扩报装流程**（申请→勘察→审批→装表→归档） | 辽宁规范 I/II/III 级均要求；`ReportInstallPort` 已预留 stub | 现行立户向导=直接建档，适合水司直管；审批流是 II/III 级能力，建议做成可选工单类型 |
| S2 | **表务工单化**（装/换/拆/校派发-回执-审批） | 辽宁规范 I 级即含表务管理 | 现在 MeterInstallation 是直接操作留痕；工单化=把操作挂进 Task 派发流，技术上可复用任务中心 |
| S3 | **网上营业厅/用户自报读数** | 辽宁 II/III 级 | B2C 入口，本质是第二个前端工程；不建议现在做 |
| S4 | **移动抄表 APP**（拍照/GPS 轨迹） | 辽宁 III 级 | `ReadSource.APP` 已预留；建议暂不投入 |
| S5 | **产销差率/NRW** | 行业核心 KPI | 需要供水总量（生产侧）数据；可先做「月度供水总量手工录入 + 产销差率指标」最小闭环 |
| S6 | **发票开具对接税控** | 政企客户刚需 | 工作量大且依赖外部税务通道，建议仅登记不直连 |
| S7 | **大用户管理视图** | 辽宁 III 级 | 可用统一查询近似实现，低优先 |

## 四、结论建议

**建议本轮补齐 G1–G5**（G6 视是否用手持机而定）——它们都是收费主链路上的断点，且多数基建已在（PENALTY 枚举、SmsPort/ReportInstallPort 端口、任务中心、异常队列）。

**S 级建议暂缓，先向客户确认部署形态**：目标客户若是「水司内部营收+集抄」则 S1/S2 价值高（任务中心可复用）；若含 C 端服务再考虑 S3。

P0 候选排序（按价值/成本）：G1 违约金 > G3 对账 > G4 催缴通知 > G5 票据台账 > G2 代扣文件流（最大项，可再拆 出盘/回盘/呆账 三步）。
